# 第一章 绪论（草稿）

## 1.1 研究背景与意义

随着大语言模型（Large Language Model, LLM）能力的快速提升，以 LLM 为核心的智能体（Agent）系统通过工具调用（Tool Calling）与外部环境交互，已广泛应用于办公自动化、金融理财、旅行预订等场景。然而，工具集成在扩展智能体能力边界的同时，也引入了新的攻击面：网页、邮件、文档、API 响应等外部数据中可能隐藏恶意指令，智能体在读取时可能将其误解为合法指令并加以执行，此类攻击被称为间接提示注入（Indirect Prompt Injection）。

从信息论的视角看，提示注入的本质在于指令与数据共享同一传输信道：LLM 输入端无法从符号流本身区分"来自可信用户的指令"与"来自外部数据的内容"，即信道缺乏可靠的信源标识。为缓解这一问题，主流方法在训练与推理层面建立指令层次（Instruction Hierarchy），依据系统、用户、助手、工具输出等角色的优先级约束模型行为，而该层次依赖于聊天模板（Chat Template）中的特殊角色标记（如 system、user 标记）对输入进行结构化分割。ChatInject 的研究表明，这种基于特殊 token 的分割机制本身构成了新的攻击面：攻击者可以在低优先级的工具输出中伪造角色标记，使恶意指令获得高优先级角色的"权威性"。复现并验证这一漏洞机制，对理解智能体系统的安全边界、设计更可靠的防护方案具有重要意义。

## 1.2 ChatInject 论文概述

ChatInject（Chang et al., ICLR 2026）针对工具集成 LLM 智能体提出了一种滥用聊天模板的间接提示注入攻击。论文将攻击场景形式化为：用户指令触发智能体调用某工具，攻击者在该工具返回的内容中嵌入恶意指令，目标是诱导智能体执行恶意指令（如调用另一工具完成转账、泄露数据等）。在攻击构造上，论文比较了四种 payload 变体：Default InjecPrompt，即传统的明文注入；InjecPrompt + ChatInject，将注入前缀与恶意指令分别包裹于目标模型模板的 system 与 user 角色标记中；Default Multi-turn，以明文形式嵌入一段劝导式多轮对话；Multi-turn + ChatInject，将多轮对话的每一轮均按角色标记模板化，从而在一次性工具输出中伪造完整的对话历史。在此基础上，论文还提出利用 think 与 tool_call 标记的推理钩子与工具调用钩子，进一步模拟智能体的内部行为结构。

实验基于 AgentDojo 与 InjecAgent 两个基准、9 个前沿模型，以攻击成功率（Attack Success Rate, ASR）与攻击下可用性（Utility under Attack）为核心指标。论文的主要发现包括：其一，ChatInject 显著提升平均 ASR，AgentDojo 上由 5.18% 升至 32.05%，InjecAgent 上由 15.13% 升至 45.90%，多轮变体在 InjecAgent 上平均达 52.33%；其二，模板化 payload 具有强跨模型迁移能力，对模板结构未知的闭源模型同样有效；其三，提示层防御依然可能被绕过，而外部检测器虽能降低 ASR，但通常伴随一定的 Utility 损失。

## 1.3 本文研究内容与组织结构

本文作者在小组中负责课程论文的复现部分。具体工作包括三个方面：其一，基于论文官方开源代码（AgentDojo 框架的 ChatInject 扩展）搭建可复现的实验环境，并针对可用的模型 API 接入方式做适配；其二，实现论文提出的四种攻击 payload 变体以及推理、工具调用钩子，在 AgentDojo 基准的银行、旅行与 Slack 三个应用域共 389 个测试用例上，以 DeepSeek API 模型为初始受试智能体，并增补 GLM-5.3-Flash 与 Qwen3.7-Flash，对每种模型运行七种攻击设置与一组无攻击基线；其三，统计各设置下的 ASR 与 Utility 指标，与原论文报告的结果进行趋势对比，并分析差异来源。

本报告组织如下：第一章为绪论；第二章介绍 ChatInject 攻击方法的复现，包括复现目标与实验设计、攻击原理与实现机制、实验环境与数据集配置、代码复现与执行过程、复现结果及与原论文的对比、复现问题与差异说明；第三章与第四章分别介绍小组后续承担的改进工作与结果分析。
